> **TL;DR**
>
> Smart CCTV에서 오인식·미인식이 발생했을 때, 많은 원인은 의외로 알고리즘이 아닌 **데이터에서 발생합니다.** 데이터를 보지 않고 알고리즘만 바라볼 경우 모델만 계속 교체하면서 카메라 각도 하나로 해결될 문제를 붙잡고 있게 됩니다.
>
> **Probe Quality Evaluation**은 CCTV영상에서 face bbox GT를 라벨링한 뒤, **얼굴 등록 DB를 아예 쓰지 않고** 세 가지 질문에 순서대로 답하는 과정입니다.
>
> - **Q1** CCTV 영상 안에서 사람이 식별되는가
> - **Q2** 프레임 품질 점수가 정말 식별 성패를 예측하는가
> - **Q3** 완벽한 프레임 선별기가 있다면 성능이 어디까지 오르는가
>
> 순서가 중요합니다. Q1이 무너져 있으면 매칭 규칙·임계값 등을 아무리 손봐도 얻을 것이 없고, Q3의 성능이 현재 성능과 붙어 있으면 품질 게이트를 만드는 작업 자체가 낭비입니다.

## 1. 용어 정리 — Probe와 Gallery

얼굴 인식 시스템의 평가를 이야기하려면 두 용어부터 정리해야 합니다.

### Probe (프로브)

- **정의**: 시스템이 "이 사람이 누구인지 찾아내라"고 입력받는 **조회용(검색용) 이미지·동영상 데이터**
- **역할**: 정답을 찾기 위해 질문을 던지는 주체
- **예시**
    - CCTV에 촬영된 인물의 얼굴 영역 Bounding Box
    - 공항 출입국 관리대 카메라에 찍힌 **승객의 현재 얼굴 사진**
    - 관제 시스템에서 추적하고자 하는 **수배자의 CCTV 캡처 화면**

### Gallery (갤러리)

- **정의**: Probe와 비교할 수 있도록 미리 등록되어 있는 **참조 데이터베이스(Reference DB)** 집합
- **역할**: Probe가 들어왔을 때 "이 중에 일치하는 사람이 있는가?"를 찾기 위해 뒤지는 대상
- **예시**
    - Smart CCTV 시스템에 저장된 **사람 사진 DB**
    - 여권 정보 시스템에 저장된 **여권 사진 DB**
    - 기업 출입 시스템에 등록된 **전 직원 사원증 사진 DB**

즉 **Probe는 현장에서 방금 들어온 얼굴**, **Gallery는 미리 잘 찍어 등록해 둔 얼굴**입니다. 이 비대칭이 이 글의 출발점입니다. Gallery는 통제된 환경에서 한 번 잘 찍으면 되지만, Probe는 매 순간 통제되지 않은 현장 조건에 그대로 노출됩니다.

## 2. 왜 Probe Quality를 측정해야 하는가

Smart CCTV 시스템은 Face Embedder(e.g., insightface) 모델로 Probe와 Gallery 간의 유사도(Similarity)를 측정하여 인물을 식별합니다. 운영 중 오인식이나 미인식이 발생할 때, 원인은 크게 두 가지로 나뉩니다.

1. **알고리즘 문제**: 데이터에 신원 정보가 충분한데 모델 성능이나 Threshold 설정이 미흡한 경우 → 소프트웨어 개선으로 해결 가능
2. **데이터 품질 문제 (여기선 Probe Quality로 제한)**: 화질 저하, 각도, 얼굴 픽셀 부족으로 **임베딩에 신원 정보 자체가 담기지 않는** 경우 → 소프트웨어로 일부 보완할 수 있지만, 하드웨어·환경 개선이 비용적으로 더 저렴한 경우가 많음

문제는 이 둘이 **증상만으로는 구분되지 않는다**는 점입니다. "특정 카메라에서만 사람을 못 알아본다"는 현상은 모델이 부족해서일 수도 있고, 그 카메라가 천장에 너무 높이 달려 있어서일 수도 있습니다. 원인을 나누지 못하면 개선 작업이 계속 모델 교체와 Threshold 수정에만 머무릅니다.

그리고 **Gallery 쪽 지표만으로는 2번을 볼 수 없습니다.** 등록 사진이 아무리 완벽해도 Probe 쪽에 신원 정보가 없으면 어떤 매칭 규칙도 맞힐 수 없는데, Gallery 품질 지표는 그 상황에서도 "이상 없음"을 냅니다. 그래서 **Probe Quality를 Gallery Quality와 독립적으로** 측정해야 합니다.

> **Probe Quality 측정의 목적**
>
> **CCTV 현장 데이터(Probe) 자체가 인물 식별이 가능한 수준인가를 Gallery와 독립적으로 검증**하여, 알고리즘 개선과 하드웨어 조치 중 **어느 쪽에 예산을 쓸지**를 근거로 결정하는 것입니다.

이 글은 Probe 한쪽만 다룹니다. Probe와 Gallery 사이의 매칭(도메인 차이, 임계값 설계, 등록 방식)은 별도의 주제로 추후에 다루겠습니다.

## 3. Ground Truth(GT) 라벨링 — 측정의 전제

측정은 사람이 라벨링한 GT에서 시작합니다.

라벨링 방안:

- CCTV 영상 내 각 사람의 얼굴 영역에 **Face Bounding Box**를 설정합니다.
- 단순 영역 지정에서 끝내지 않고, 동일 인물에게 **고유 ID(Person ID)** 를 부여합니다. 이 ID가 있어야 "같은 사람끼리의 유사도"와 "다른 사람끼리의 유사도"를 나눠서 볼 수 있습니다.

![분홍색 배경의 스튜디오에 고양이, 회색 푸들, 코기, 고양이 네 마리가 나란히 있는 사진. 각 동물의 얼굴 영역에만 노란색 사각형 bounding box가 그려져 있고 box 위에 pet-001부터 pet-004까지 ID 라벨이 붙어 있다. 카메라와의 거리에 따라 box 크기가 서로 다르고, 맨 오른쪽 pet-004는 측면 얼굴만 잡혀 있다](/images/probe-evaluation/face-bbox-ex.png)

*얼굴 영역에 bounding box를 치고 개체마다 고유 ID를 부여한 라벨링 예시. 프라이버시 보호를 위해 실제 사람이 아닌 애완동물 이미지로 치환했습니다 (이미지의 `pet-001`이 아래 스키마의 `person-001`에 해당)*

이렇게 라벨링한 결과는 프레임 단위로 다음과 같은 구조로 쌓입니다.

```json
{
  "recording_id": "rec-001",
  "camera_id": "cam-001",
  "frames": [
    {
      "frame_number": 12165,
      "timestamp": 845.8019,
      "detections": [
        {
          "person_id": "person-001",
          "face_bbox": { "x": 305, "y": 214, "w": 28, "h": 36 },
          "occluded": false,
          "blurred": false
        },
        {
          "person_id": "unknown",
          "face_bbox": { "x": 517, "y": 209, "w": 25, "h": 35 },
          "occluded": false,
          "blurred": false
        }
      ]
    }
  ]
}
```

여기서 각 필드는 단순한 기록이 아니라, 뒤에서 이야기할 분석 축과 그대로 대응됩니다.

| 필드 | 이후 분석에서의 역할 |
| --- | --- |
| `camera_id` | 카메라별 grouping 분석(7-2)의 기준 |
| `recording_id` | 영상 녹화 단위 |
| `frame_number` / `timestamp` | 프레임 시간차 확보 및 프레임 샘플링 간격 산정 |
| `person_id` | Intra(동일 ID 쌍) / Inter(다른 ID 쌍)를 나누는 기준 |
| `face_bbox` | Crop 영역. `w`·`h` 자체가 **얼굴 해상도 지표**가 됨 |
| `occluded` / `blurred` | 저품질 프레임 필터링 및 원인 분류의 근거 |

라벨링 스키마를 설계할 때 **"어떤 축으로 grouping해서 볼 것인가"를 먼저 정해야 합니다.** `camera_id`를 남기지 않았다면 나중에 카메라별 비교를 할 수 없고, `recording_id`가 없다면 서로 다른 녹화본과 비교할 수 없습니다.

### 신원을 분리한다

라벨링에는 특정 인물로 확정할 수 없는 얼굴이 반드시 섞입니다. 이런 값은 따로 라벨링한 후 지표에서 제외해야 합니다.

- `unknown` — 누구인지 모름
- `uncertain` — 라벨러가 확신하지 못함

제외된 얼굴이 몇 개인지는 리포트에 반드시 남깁니다. 라벨된 얼굴의 상당수가 미판정 신원인 경우가 흔한데, 이 사실을 적어 두지 않으면 최종 프로브 개수만 보고 표본이 충분하다고 오판하게 됩니다.

## 4. CCTV 안에서 서로 다른 사람을 식별할 수 있는가?

첫 질문은 Prob간 유사도 비교입니다. 이 값은 갤러리의 품질과 무관하게 "프로브(CCTV 영상)에 신원 정보가 실려 있는가"에 직접 답합니다.

- **Intra-Similarity (동일인 유사도)**: 동일한 ID를 가진 인물 간의 유사도. **높을수록 정상**
- **Inter-Similarity (타인 유사도)**: 서로 다른 ID를 가진 인물 간의 유사도. **낮을수록 정상**

두 지표는 함께 봐야 의미가 있습니다. Intra가 낮다는 것은 **같은 사람을 같은 사람으로 묶지 못한다**는 뜻이고(미인식 위험), Inter가 높다는 것은 **서로 다른 사람을 구분하지 못한다**는 뜻입니다(오인식 위험).

> **주의사항 — 프레임 시간차 확보**
>
> 동일 인물의 Intra-Similarity를 측정할 때는 **최소 수십 프레임 이상(또는 수 초 이상)의 시간차**를 두고 수집해야 합니다. 인접 프레임(1~2 Frame) 간 비교는 인물의 특징이 같아서 점수가 높은 것이 아니라 **픽셀 차이가 거의 없어서 높게 나오는 착시**입니다. 이 함정에 빠지면 실제로는 식별에 부적합한 영상을 "Intra 0.95, 문제 없음"으로 오판하게 됩니다.

### 4-1. 분리 격차(Separation Gap) — 평균이 아니라 '꼬리'를 봐야 하는 이유

Intra와 Inter를 각각 따로 보는 것만으로는 정확한 판정이 어렵습니다. 핵심은 **두 분포를 명확히 가를 수 있는 기준선이 존재하느냐**이며, 이를 하나의 지표로 수치화한 것이 분리 격차(Separation Gap)입니다.

$$\text{분리 격차} = \text{Intra}_{p05} - \text{Inter}_{p95}$$

> * **$\text{Intra}_{p05}$**: 동일인 유사도 분포의 **하위 5%** 수치 (최악의 동일인 유사도)
> * **$\text{Inter}_{p95}$**: 타인 유사도 분포의 **상위 95%** 수치 (최고의 타인 유사도)

#### 왜 평균/중앙값이 아닌 '꼬리(Percentile)'를 볼까요?

![alt text](/images/probe-evaluation/seperation-gap.png)

실제 모델의 오인식·미인식이 결정되는 지점은 분포의 가운데가 아니라 두 분포가 만나는 경계선(꼬리 영역)이기 때문입니다. 아무리 중앙값 사이의 거리가 멀어도 꼬리가 서로 겹쳐 있다면 실무 환경에서는 오작동을 피할 수 없습니다.

#### 결과 해석과 실무적 의의

* **분리 격차가 양수**: Intra와 Inter 분포 사이에 명확한 경계가 존재합니다. 두 그룹을 깔끔하게 가르는 Threshold(임계값)를 설정할 수 있습니다.
* **분리 격차가 음수**: 동일인 유사도가 타인 유사도보다 낮아지는 역전 구간(분포 겹침)이 존재합니다. **이 상태에서는 어떤 Threshold를 적용하더라도 False Positive(오인식)와 False Negative(미인식)를 동시에 막을 수 없습니다.**

분리 격차가 음수라면 임계값 튜닝으로 시간을 허비할 것이 아니라, **영상 품질 개선이나 모델 재학습으로 방향을 전환해야 함**을 즉시 알 수 있습니다. 이 단 한 줄의 지표가 몇 주간의 불필요한 튜닝 작업을 선제적으로 막아줍니다.

### 4-2. Leave One Out rank-1

유사도 분포는 "같은 인물을 Embedder로 묶을 수 있는지, 서로 다른 인물을 분리할 수 있는지"에 답하지만, "그래서 몇 %를 맞히는가"에는 답하지 않습니다. 이에 답하기 위해 Gallery 없이 Probe끼리 서로를 식별시켜 봅니다. 프로브 이미지 하나를 골라, 나머지 프로브 이미지들을 후보로 두고 가장 닮은 인물을 고르게 하는 방식입니다(Leave-One-Out).

설계에서 반드시 지켜야 할 것이 세 가지 있습니다.

1. **같은 촬영 세션을 후보에서 제외합니다:** 같은 영상을 후보에 남기면 인접 프레임이 자기 자신을 알아보는 것을 식별 성공으로 측정할 수 있습니다.
2. **우연 수준을 함께 적습니다:** 기준은 **1/(후보 인물 수)** 입니다. 이미지 수가 아니라 인물 수입니다. 후보 인원이 다르면 rank-1을 나란히 놓을 수 없습니다. 후보 3명에서의 40%는 우연 수준(33%)과 거의 같지만,
후보 15명에서의 34%는 우연(6.7%)의 다섯 배입니다.
아래 3번 규칙 때문에 프로브마다 후보 인물 수가 달라지므로, 전체 우연 수준은 프로브별 1/Nᵢ를 평균해서 구합니다.
3. **정답 인물이 후보에 없는 프로브는 분모에서 뺍니다.** Leave One Out으로 빼둔 프로브 이미지에 해당하는 인물이 다른 녹화본에 한 번도 등장하지 않으면 후보 목록에 오르지 못해 **무슨 답을 내도 오답**이 됩니다.

LOO rank-1은 저화질끼리 붙이는 실험(LR-LR)입니다. 실제 운용은 고화질 등록사진과 저화질 프로브를 붙입니다(HR-LR). 조건이 다르고, 차이가 두 방향으로 작용합니다.

- 카메라·화각·조명·압축이 같아 도메인 갭이 없다 → LOO에 유리
- 양쪽 다 이미지 정보가 부족하다 → LOO에 불리

그래서 LOO를 실제 성능의 상한으로 읽으면 안 됩니다. [LR-LR은 문헌에서도 같은 해상도의 HR-LR보다 일관되게 더 어려운 조건으로 다뤄집니다](https://arxiv.org/abs/2608.06580) — 저해상도 얼굴 인식 연구에서 벤치마크 쌍을 한 장만 저해상도화한 HR→LR과 양쪽 모두 저해상도화한 LR→LR로 나눠 재면, 후자를 "더 어려운 하한(harder bound)"으로 둡니다. 즉 LOO가 낮아도 등록 사진을 다시 찍으면 실제 성능은 오를 수 있습니다.

LOO가 답해주는 것은 하나입니다.**이 CCTV 영상 집합 안에서 인물들이 서로 구분되는가.**
값이 우연 수준에 근접하면 프로브에서 뽑히는 임베딩에 신원 신호가 거의 없다는 뜻이고, 그 상태에서 매칭 임계값을
조정하는 일은 의미가 없습니다. 
먼저 원인을 분석해야 합니다. 검출 실패인지, 랜드마크 정렬이 틀렸는지, 얼굴 픽셀 수가 모자란지, 모션 블러인지 등.

## 5. 프레임 선별로 얼마나 개선될 수 있는가

4절에서 영상에 신원 정보가 있다는 것을 확인했다면, 다음으로 떠오르는 대응책은 프레임 선별입니다. 현실적으로 모든 프레임을 완벽하게 각 사람별로 분리하는 것은 난이도가 매우 높습니다. 따라서 품질 점수가 낮은 프레임은 버리고, 상태가 좋은 프레임만 골라 인식을 시도하는 방식이 현실적입니다.

그런데 이를 위한 **품질 선별 게이트(Quality Gate)를** 구축하는 데는 상당한 비용이 듭니다. 품질 점수 산출 로직을 여러 개 구현 및 검증해야 하고, 적절한 임계값(Threshold)을 설정해 운영 환경에서 관리해야 하기 때문입니다. 따라서 **착수 전에 먼저 확인해야 할 것이 있습니다. 프레임 선별이 잘 됐을 때 최대로 얻을 수 있는 개선폭이 얼마인가.** 이 폭이 애초에 작다면 이후의 작업은 전부 헛수고입니다.

### 5-1. 오라클로 성능 한계를 측정한다

정답 라벨을 써서 반칙으로 만든 점수를 **오라클(Oracle)** 이라고 부릅니다. 프로브마다 다음과 같이 계산합니다.

1. 해당 프로브와 **같은 인물** 이미지들 사이의 유사도 분포
2. 해당 프로브와 **다른 인물** 이미지들 사이의 유사도 분포
3. 두 분포가 얼마나 명확히 분리되는지(동일인 유사도는 높고, 타인 유사도는 낮은 정도)를 점수화한다

두 분포가 잘 나뉘어 있는 프로브일수록 높은 점수를 받습니다. [SDD-FIQA](https://arxiv.org/abs/2103.05977)가 학습용 정답 점수를 만들 때 쓰는 방식과 같습니다. 단, 프로브에서 정답을 알아야 계산되니 실제 서비스에 넣을 수는 없습니다. 목적은 배포가 아니라 **"프레임을 가장 잘 골라냈을 때 오류율이 어디까지 내려가는가"** 를 측정하는 데 있습니다.

### 5-2. Error-versus-Reject Characteristic(ERC) 곡선으로 그린다

![가로축이 버린 비율(rejection rate)로 0%에서 80%까지 늘어나고, 세로축이 rank-1 오류율로 0%에서 40%인 꺾은선 그래프. 회색 점선이 아무것도 버리지 않았을 때의 오류율 35%를 나타낸다. 주황색 오라클 곡선은 35%에서 시작해 초반에 급하게 떨어진 뒤 점점 완만해지며, 80%를 버린 지점에서 1.5% 근처에 도달한다](/images/probe-evaluation/ERC-curve.png)

점수가 낮은 프로브부터 차례로 버리면서, 남은 프로브의 rank-1 오류율(1 − rank-1)을 기록합니다. 가로축은 버린 비율(rejection rate), 세로축은 오류율입니다. 아무것도 버리지 않은 왼쪽 끝이 4절의 값이고, 버릴수록 값이 내려가는 모양이 됩니다. 이 곡선을 [ERC(Error-versus-Reject Characteristic) 또는 EDC(Error-versus-Discard Characteristic) 곡선](https://arxiv.org/abs/2009.01103)이라고 부릅니다.

오라클로 그린 곡선이 **하한선**입니다. 정답을 모르는 어떤 품질 점수도 이 아래로 내려갈 수 없습니다.

> **참고 — ERC 곡선을 읽는 법**
>
> ERC는 인식 모델이 아니라 **품질 평가 모델(FIQA)의 선별 능력**을 재는 곡선입니다. ROC나 DET가 인식 모델(Matcher) 자체의 성능을 잰다면, ERC는 그 앞단에서 **무엇을 버릴지 고르는 능력**을 잽니다. 세로축의 오류율로 문헌에서는 보통 FNMR(False Non-Match Rate)을 쓰지만, 이 글은 4절에서 rank-1로 식별 성패를 판정했으므로 그에 대응하는 rank-1 오류율을 놓았습니다.
>
> 읽을 때 보는 것은 세 가지입니다.
>
> - **버린 비율 0에서의 오류율** — 아무것도 버리지 않았을 때의 기본 인식 성능. 이 글에서는 4절 LOO rank-1의 오류율에 해당합니다.
> - **곡선의 기울기** — 조금만 버렸는데도 오류율이 급하게 떨어지면, 품질 점수가 실제 인식 난이도를 정확히 반영한다는 뜻입니다. 반대로 완만하다면 인식 성패와 무관한 기준을 품질로 착각하고 있다는 의미입니다.
> - **AUEC(Area Under ERC)** — ERC 곡선 아래 면적으로 선별 능력을 단일 수치로 요약합니다. 오류율을 세로축에 놓은 곡선이므로 **면적이 작을수록** 좋습니다. 6절에서 쓰는 AUROC와 이름만 비슷하고 다른 값입니다. AUROC는 품질 점수가 정오를 얼마나 잘 순서 매기는지를 재는 ROC 곡선의 면적이라 **클수록** 좋습니다.
>
> 곡선끼리 비교할 때는 **같은 버린 비율 구간에서** 봐야 합니다. 많이 버리면 어떤 점수를 써도 오류율은 내려가므로, 버린 비율을 맞추지 않은 비교는 성립하지 않습니다.

### 5-3. 곡선을 읽고 착수 여부를 정한다

![오라클 ERC 곡선을 나란히 놓은 두 개의 꺾은선 그래프. 두 그래프 모두 가로축은 버린 비율(rejection rate)로 0%에서 60%까지 늘어나고, 세로축은 남은 프로브의 rank-1 오류율이다. 회색 점선이 현재 오류율인 0.38을 나타낸다. 왼쪽 '하한선이 붙어 있음' 그래프에서는 주황색 오라클 하한선이 0.38에서 0.35까지만 완만하게 내려가 점선과 거의 붙어 있다. 오른쪽 '간격이 벌어짐' 그래프에서는 초록색 오라클 하한선이 0.38에서 0.12까지 뚜렷하게 내려가고, 점선과 곡선 사이의 넓은 영역이 '6절이 노릴 구간'으로 칠해져 있다](/images/probe-evaluation/oracle-erc-two-cases.png)

*오라클 ERC 곡선의 두 가지 경우. 왼쪽은 가장 잘 골라도 얻을 것이 없는 상태이고, 오른쪽의 칠해진 영역이 품질 점수로 노릴 수 있는 최대치입니다*

- **하한선이 현재 오류율과 거의 붙어 있다면** 여기서 멈춥니다. 가장 잘 골라도 얻을 것이 없다는 뜻이므로, 어떤 품질 점수를 만들어도 이길 것이 없습니다. 병목은 다른 곳에 있습니다. 해상도, 카메라 화각, 등록 사진(갤러리) 방식을 먼저 봐야 합니다. **품질 게이트 개발을 착수하지 않는 것이 옳은 결정입니다.**
- **벌어져 있다면** 그 간격이 6절에서 노릴 수 있는 최대치입니다. 목표치를 이 간격 안에서 잡습니다. 오라클은 정답을 보고 고르므로, 실제 점수가 이 간격을 전부 먹는 일은 없습니다.

> **주의**: 오라클의 AUROC는 읽지 않습니다. 4절의 정오 판정을 만든 그 유사도에서 점수가 나오므로 구조적으로 낙관 편향이고, 거의 동어반복입니다. 오라클에서 읽어야 할 것은 ERC 곡선이 어디까지 내려가는지뿐입니다.

## 6. 어떤 품질 점수가 실제로 예측력이 있는가

5절에서 간격을 확인했다면, 이제 정답 없이 계산되는 점수로 그 간격을 얼마나 메울 수 있는지 봅니다.

여기서 검증을 건너뛰면 **좋은 프레임을 버리고 나쁜 프레임을 남기는 게이트**를 만들어 놓고 성능이 왜 안 오르는지 모르게 됩니다. 그래서 4절에서 나온 프로브별 정오(맞았는가 / 틀렸는가)를 정답으로 두고, 각 점수 후보가 그 정오를 얼마나 잘 예측하는지 AUROC로 재는 것부터 시작합니다.

### 6-1. 후보를 출처별로 세운다

| 출처 | 후보 예시 |
| --- | --- |
| **임베딩 모델** | SER-FIQ, 임베딩 벡터의 크기(norm) |
| **Detector·Landmark** | Detector 신뢰도, 정면도, yaw 절댓값, 두 눈 사이 거리, 코 위치 오프셋 |
| **픽셀** | 정렬된 crop의 Laplacian 분산(블러) |
| **박스 크기** | 얼굴 최소변 px |
| **앵커** | Random(난수) |

[SER-FIQ](https://arxiv.org/abs/2003.09373)는 Dropout을 켠 상태로 같은 얼굴을 여러 번 통과시켜, 임베딩이 얼마나 흔들리는지를 재는 방식입니다. 흔들림이 작을수록 그 얼굴이 모델에게 안정적으로 보인다는 뜻입니다. 단, **Dropout module 없이 학습된 모델에서는 SER-FIQ 값을 신뢰할 수 없습니다.** [공식 구현](https://github.com/pterhoer/FaceImageQuality)이 forward pass마다 dropout mask를 다르게 걸어 그 편차를 재는 구조이므로, dropout layer가 없으면 흔들림 자체가 발생하지 않습니다.

여기서 두 가지 설계가 중요합니다.

**난수 앵커를 반드시 넣습니다.** 우연이 어디인지 보여주는 기준선입니다. 앵커 없이 AUROC 0.57을 보면 "약한 신호가 있다"고 읽게 됩니다. 하지만 앵커가 0.50이고 신뢰구간이 0.5를 걸치고 있으면 그냥 잡음입니다. 이 줄보다 못한 후보는 쓸 수 없습니다.

**모든 후보를 "높을수록 좋다"로 맞춰 놓습니다.** yaw를 원래 값 그대로 넣으면 −40° 얼굴만 버려지고 +40°는 남아서 지표가 조용히 헛돕니다. 품질은 각도의 크기에 달렸지 부호에 달려 있지 않습니다.

### 6-2. 전역 AUROC만 보면 안 된다

![품질 점수를 가로축으로 놓고 프로브를 점으로 찍은 도트 플롯. 인물 A·B·C 세 줄에서는 각각 틀린 프로브(빈 주황 동그라미)가 왼쪽, 맞은 프로브(채운 초록 동그라미)가 오른쪽에 모여 있어 AUROC가 0.89, 0.91, 0.94로 높다. 하지만 세 인물의 점수 구간이 서로 어긋나 있어, 아래쪽 '전역' 줄에서 모두 합치면 맞음과 틀림이 뒤섞이고 AUROC가 0.52로 떨어진다](/images/probe-evaluation/stratified-auroc.png)

*인물 안에서는 품질 점수가 정오를 잘 가르는데, 인물을 합치면 신호가 사라지는 구조. 심슨의 역설의 전형적인 예입니다*

인물별 식별 난이도가 크게 벌어져 있으면 **전역 AUROC는 0.5로 눌립니다.** "품질이 낮아서 틀린 것"과 "그 사람이 원래 안 맞는 것"이 한 덩어리로 섞이기 때문입니다. [심슨의 역설](https://en.wikipedia.org/wiki/Simpson%27s_paradox)이 일어나는 전형적인 구조입니다.

그래서 **인물 안에서만 측정하고, 인물별 표본 크기로 가중평균**합니다. 층화하면 전역에서 0.5 근처에 눌려 있던 후보가 뚜렷한 예측력을 보이는 일이 흔합니다.

이때 난수 앵커가 두 축 모두에서 0.5 근처에 남아 있는지 확인합니다. 앵커까지 같이 올라간다면 층화 방식 자체가 값을 부풀리고 있다는 뜻입니다.

리포트에는 **전역과 층화(Stratified)를 둘 다** 싣습니다. 전역만 실으면 "품질 지표는 무의미하다"는 잘못된 결론이 남고, 층화만 실으면 "인물을 모르는 실제 게이팅 상황에서는 이만큼 안 나온다"는 사실이 사라집니다.

### 6-3. 신뢰구간은 인물 단위로 재표집(Resample)한다

품질 점수 후보 하나의 AUROC가 **0.58**로 나왔다고 해봅시다. 우연 수준인 0.5보다 높으니 게이트에 넣어도 될까요. 아직 아닙니다. 이 숫자 하나로는 **소수의 인물이 신호를 통째로 끌고 있는 경우**를 걸러낼 수 없습니다.

CCTV 영상은 인물별 프로브 수가 심하게 치우칩니다. 한 카메라에서 라벨된 프로브 100장 중 80장이 인물 A의 것이고 나머지 20장이 지나가던 사람들의 것인 상황이 흔합니다. 이때 품질 점수가 우연히 인물 A에게만 잘 맞았다면, 다른 사람에게는 쓸모없는 점수인데도 전체 AUROC는 0.58까지 올라갑니다.

그래서 물어야 할 것은 "이 프로브들에서 우연인가"가 아니라 **"다른 사람이 들어와도 남는 신호인가"** 입니다. 부트스트랩을 프로브 단위로 돌리면 앞의 질문에 답하게 됩니다. 인물 A의 프로브 80장이 매번 다시 뽑혀 들어오므로 착시가 그대로 유지됩니다. 재표집(Resample) 단위를 **인물**로 잡아야(cluster bootstrap) 뒤의 질문에 답할 수 있습니다.

방법은 이렇습니다. 프로브를 한 장씩 섞는 대신 **인물을 단위로 통째로** 복원추출해 가상의 데이터셋을 수천 개 만들고, 그때마다 AUROC를 다시 계산합니다. 이렇게 원본 표본을 재조합해 지표의 흔들림을 재는 기법을 **부트스트랩(Bootstrap)** 이라고 부릅니다. 수천 개의 값에서 위아래 2.5%씩을 잘라내면 **95% 신뢰구간**이 되고, 이 구간은 "어떤 인물 조합이 걸리느냐에 따라 성적이 어디까지 오르내리는가"를 보여줍니다.

판정은 점추정치가 아니라 구간의 **하한**으로 합니다.

- **탈락 — 점추정치 0.58, 구간 [0.48, 0.68]**: 인물 조합이 불리하게 걸리면 0.48까지, 즉 우연 수준 아래로 내려갑니다. 0.58은 특정 몇 명 덕에 나온 값입니다.
- **통과 — 점추정치 0.56, 구간 [0.51, 0.61]**: 점추정치는 오히려 낮지만, 가장 불리한 조합에서도 0.51로 우연 수준을 넘습니다. 인물이 바뀌어도 남는 신호입니다.

**95% 신뢰구간의 하한이 0.5를 넘는 후보만 "신호가 있다"고 말할 수 있습니다.** 점추정치가 아무리 그럴듯해도 하한이 0.5를 걸치면 게이팅에 쓸 수 없습니다.

![품질 점수 후보 여섯 개의 AUROC를 점과 신뢰구간 막대로 표시한 forest plot. 가로축은 인물 단위 부트스트랩 95% 구간의 AUROC이고 0.5에 세로 점선이 있다. SER-FIQ(0.66), 두 눈 사이 거리(0.62), 임베딩 norm(0.59)은 구간 하한이 0.5보다 오른쪽에 있어 초록색 '통과'로 표시된다. Laplacian 분산(0.56), 박스 최소변 px(0.54), 난수 앵커(0.50)는 구간이 0.5 점선을 걸치고 있어 회색 '탈락'으로 표시된다](/images/probe-evaluation/candidate-auroc-ci.png)

*후보별 예측력과 인물 단위 부트스트랩 신뢰구간. 하한이 0.5를 넘는 세 후보만 게이팅에 쓸 수 있고, 난수 앵커와 구간이 겹치는 후보는 탈락입니다*

여기서 직관과 어긋나는 결과가 자주 나옵니다. "화질이 나쁘면 못 알아본다"는 상식과 달리, 블러 지표나 박스 크기가 단독 기준으로는 신뢰구간을 통과하지 못하는 경우가 있습니다. 상식을 지표로 확인하는 것이 이 절의 목적입니다.

### 6-4. 최종 결정은 AUROC가 아니라 ERC로 한다

AUROC는 순서를 얼마나 잘 매기는지를 잽니다. 하지만 운영에서 정해야 하는 것은 **"하위 몇 %를 버리면 오류율이 얼마가 되는가"** 입니다. 신뢰구간을 통과한 후보로 5-2와 같은 ERC 곡선을 그리고, 5절의 오라클 하한선과 겹쳐 봅니다. 하한선에 얼마나 근접했는지가 그 후보의 실질 성적이고, 스킵 임계값도 이 곡선에서 정합니다.

이때 **인물 안에서 버려야 합니다.** 전역으로 버리면 품질 점수가 전반적으로 낮게 깔린 인물이 통째로 사라져, 곡선이 "품질을 걸렀다"가 아니라 **"쉬운 사람만 남겼다"** 를 측정하게 됩니다.

## 7. 조건별 Grouping 분석

같은 숫자를 어떤 축으로 쪼개느냐에서 조치가 나옵니다. 전체 평균 하나로는 아무것도 도출되지 않습니다.

### 7-1. 얼굴 크기별 — 거리 때문인가

얼굴 최소변 px를 구간으로 나눠 구간별 분리 격차와 LOO rank-1을 봅니다.

- **크기를 올릴수록 rank-1이 회복되면** 병목은 해상도입니다. 카메라 배치·줌·ROI 설정으로 움직일 수 있는 문제이고, 하드웨어 예산을 요청할 근거가 됩니다.
- **크기를 올려도 격차가 음수로 남으면** 크기만의 문제가 아닙니다. 각도·조명·Crop 규약을 봐야 합니다.

고각·광각으로 넓은 공간을 담는 CCTV에서는 인물 전체는 잡히지만 얼굴에 배정되는 픽셀은 수십 px대로 떨어집니다. InsightFace 계열의 [AuraFace v1](https://huggingface.co/fal/AuraFace-v1)은 $112 \times 112$ px을 입력값으로 받는데, [이보다 작은 얼굴은 업샘플링으로 키워도 신원 정보가 복원되지 않아 성능이 하락합니다](https://arxiv.org/abs/2608.06580). px크기가 작아지면 Embedder가 추출할 feature 자체에 정보가 부족해 Inter-Similarity가 전반적으로 높아지고, 이는 모델이 아니라 카메라 화각·설치 위치의 문제로 분류됩니다.

한 가지 덧붙이면, **박스 크기보다 두 눈 사이 거리가 정직한 유효 해상도**입니다. 박스는 자세에 따라 부풀거나 줄어들지만, 눈 간격은 얼굴이 카메라에서 얼마나 먼지를 직접 잽니다.

### 7-2. 카메라별

카메라마다 화각·거리·조명이 다르므로 **카메라는 교란 변수**입니다. 카메라가 한 대뿐이더라도 이 축을 만들어 두어야, 나중에 두 번째 카메라가 들어왔을 때 지표 정의를 바꾸지 않고 나란히 놓을 수 있습니다.

| 관찰 | 유력한 원인 | 조치 |
| --- | --- | --- |
| 특정 카메라에서만 **격차가 크게 음수** + LOO가 우연 수준 | 얼굴 픽셀 부족 또는 극단적 설치 각도 | 설치 위치·각도 조정, ROI 축소, 기종 교체 |
| 카메라별로는 정상인데 **카메라를 넘나드는 쌍에서만 Intra 저하** | 카메라 간 색감·화질 셋팅·설치 높이 불일치 | 동일 기종·동일 셋팅 표준화 |
| 얼굴 정면이 찍히는 비율이 유독 낮은 카메라 | 고각 설치 또는 동선과 어긋난 앵글 | 수평 화각 재조정 |

다중 카메라 비교는 특히 중요합니다. 카메라별로는 문제가 없는데 카메라를 넘나드는 순간 Intra가 떨어진다면, 개별 카메라 품질이 아니라 **카메라 간 일관성**이 문제입니다. 이 경우 카메라 하나를 교체해도 증상이 사라지지 않습니다.

### 7-3. 촬영 날짜 및 시간대별 분석 (Temporal / Environment Level)

#### A. 동일 날짜 / 시간차 검증 (Same-day Temporal Analysis)

**현상**: 동일한 날짜 내에서 시간차를 두고 촬영했음에도 `Intra-Similarity`이 낮게 측정되거나 `Inter-Similarity`이 높게 측정됨

**원인 분석**

1. **환경·하드웨어 요인**: 시간에 따른 조도 변화 대응 실패, 셔터 스피드 부족으로 인한 움직임 블러(Motion Blur) 발생
2. **데이터·라벨링 요인 (Face Crop 문제)**: Bounding Box가 너무 넓게 잡혀 머리 스타일, 모자, 배경 노이즈 등이 과도하게 포함된 경우
3. **피사체 요인 (가림 현상)**: 모자, 안경, 마스크, 손 가림, 깊은 숙임 등 얼굴의 주요 특징점(Landmark)을 가리는 Occlusion 발생

**대응 방안**

- **하드웨어·설정 조정**: 셔터 스피드 확보, FPS 상향, 카메라 노출·게인(Gain) 설정 자동화
- **Face Crop 표준화**: Bounding Box 가이드라인을 재정비하여 얼굴 윤곽 위주의 Tight Crop 적용 (배경·헤어스타일 영향 최소화)
- **전처리 모델 및 운영 정책 도입**
    - *알고리즘 관점*: 마스크·안경 착용 등 일부 Occlusion에도 강건한(Robust) Embedder 도입 및 Quality Score 필터링 적용
    - *운영·정책 관점*: Occlusion 비율이나 Quality Score가 일정 Threshold 미만인 경우 **'분석 불가(Low Quality / Occluded)'로 정의하여 미인식 처리**하거나, **다음 유효 프레임(Best-quality Frame)에서 재식별을 시도**하도록 정책 설정

여기서 2번(Face Crop)은 라벨링 단계에서 만들어진 문제이므로, 카메라를 바꿔도 개선되지 않습니다. 하드웨어 조치를 검토하기 전에 반드시 Crop 기준을 먼저 확인해야 하는 이유입니다.

#### B. 날짜 간격이 큰 경우 (장기 추적)

**현상**: 수개월~1년 이상 차이가 나면서 `Intra-Similarity`이 점차 저하됨

**원인**: 나이 변화, 안경·헤어스타일·체형 변경 등 자연스러운 생체·외형 변화

**대응 방안**

1. **운영 로직 개선**: 일정 주기마다 Gallery DB 갱신(얼굴 재등록)
2. **Model / Feature 영역**: 나이·외형 변화에 강건한 Multi-view / Temporal Embedding 모델 도입

이 경우는 Probe의 품질이 나빠진 것이 아니라 **Gallery가 낡은 것**이므로, 카메라 개선으로는 해결되지 않습니다.

#### C. 시간대별 차이 (낮 vs 밤)

**현상**: 주간 대비 야간(Night) 환경, 또는 조명 조건 변화 시 `Intra-Similarity` 급감 및 `Inter-Similarity` 상승

같은 "야간 성능 저하"라도 실외와 실내는 원인과 대책이 다릅니다.

**1) 실외 환경 (Outdoor)**

- **원인**
    - **자연광 부재 및 야간 저조도**: 주간 태양광 부재로 인한 광량 부족 및 이미지 센서 노이즈(Sensor Noise / Grain) 증폭
    - **명암 대비 및 역광**: 야간 가로등·차량 헤드라이트에 의한 부분 과노출(Burn-out) 및 가혹한 역광
    - **컬러 정보 손실**: 야간 카메라의 B/W(흑백) IR 모드 전환 시 색상 피처(Color Feature) 정보 상실
- **대응 방안**
    - *하드웨어*: IR(적외선) 카메라·열화상 센서 도입, 현장 보조 조명(투광등) 설치, WDR(Wide Dynamic Range) 성능 강화 기종으로 교체
    - *소프트웨어*: 저조도 디노이징(Denoising) 및 저조도 이미지 복원(Low-light Enhancement) 전처리 알고리즘 적용

**2) 실내 환경 (Indoor)**

- **원인**
    - **영업·운영 시간 외 조명 소등**: 야간 또는 휴무 시간에 실내 전등이 소등되어 조도가 급격히 하락
    - **주·야간 유입광 변동**: 낮에는 창문·출입구로 들어오는 외부 자연광과 실내 조명이 섞이지만, 밤에는 자연광이 차단되어 광원 스펙트럼과 각도가 완전히 변화
    - **인공 조명 플리커(Flicker) 현상**: 특정 저가형 LED 조명 아래에서 셔터 스피드와 주파수 불일치로 인한 주사선·깜빡임 발생
- **대응 방안**
    - *운영·하드웨어*: 최소 보안 조명(야간 상시등) 확보, Anti-Flicker(플리커 방지) 카메라 설정 활성화
    - *소프트웨어*: 실내 조명 색온도 변화에 대응하기 위한 Auto White Balance(AWB) 전처리 및 색상 보정(Color Normalization) 적용

## 9. 정리

Probe Quality Evaluation의 핵심은 **점수 자체가 아니라 점수를 어떤 축으로 쪼개서 보느냐, 그리고 그 축이 어떤 조치로 이어지느냐**에 있습니다. 전체 평균 Intra-Similarity가 0.7이라는 숫자 하나로는 아무 조치도 도출되지 않습니다. 같은 숫자를 얼굴 크기별·카메라별·인물별 등으로 나누어 보는 순간 "이 카메라의 30px 미만 구간에서만 우연 수준(현재 인식 불가)"이라는 구체적인 조치 대상이 드러납니다.

그리고 이렇게 얻은 근거는 **하드웨어 예산을 설득하는 언어**가 됩니다. "모델이 좀 부족한 것 같습니다"와 "A 카메라는 고각 설치 문제로 식별률이 40%대에 머물러 있지만, 높이를 50cm만 낮춰도 정면 얼굴이 확보되어 인식률이 정상 수준으로 회복됩니다""는 전혀 다른 무게를 갖습니다.
